# Shadow application authentication

**Approved design:** Single-owner access, Passkey first, optional backup password, 90-day remembered browser sessions, one-time 10-minute device code and QR, current/all-device logout. Existing practice data remains single-owner. No guest access to remote analysis.

**Reuse:** openGym e348fc17 provides the reference protocol and lifecycle. Shadow is MIT while openGym is AGPL; do not transplant covered source into the MIT project. Directly reuse the BSD-compatible py_webauthn verifier and browser-native WebAuthn APIs, with independently implemented Python sessions and vanilla UI. Preserve source references in documentation.

**Architecture:** New web/auth.py with separate private SQLite auth store under data_dir; opaque random session cookies hashed server-side; configured canonical public origin for WebAuthn/CSRF; authentication middleware protects pages, media and APIs. Local unconfigured mode remains usable; production keeps Basic Auth until app authentication is initialized and verified. CLI getpass setup/reset creates password hash without credentials in shell history. Device pairing issues a one-time hashed code with transactional consumption, followed by a fresh session. Privileged credential/device actions require recent authentication; recovery via local CLI invalidates sessions. No public first-user claim endpoint.

- [x] Backend and meaningful security tests: session expiry/revocation, CSRF/origin, one-time challenges and codes, registration ownership, rate limiting, protected media.
- [x] Mobile login/account UI, Passkey conversion, pairing code/QR, return-to validation and login-expired recovery preserving drafts/audio.
- [x] CLI initialization, deployment migration template and operator instructions; do not change live nginx protection before verification.
- [x] Review and full Python/Node verification; isolated browser login test. Commit/push without secrets or local data.

**Acceptance:** Password establishes the same persistent session as Passkey. Registration never grants first ownership anonymously. WebAuthn verifier checks RP/origin/challenge/UV. Device code is short lived and cannot be replayed. Logout-all and local reset revoke old credentials as specified. Existing submissions remain retryable after reauthentication. Physical Passkey ceremony requires user's device; automated signed-fixture verification is required independently of hardware.

**Verification:** 581 Python tests and 92 Node tests pass. Isolated browser verification covers protected-page redirect, password login, retained login after refresh, account settings and device QR sheet. Physical-device Passkey enrollment and production nginx migration remain operator activation steps; no production credentials were initialized.
