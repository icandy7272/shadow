# 后台分析与默写 Implementation Plan

**Goal:** 录音草稿安全保存后立即默写；后台分析不抢焦点、不打断重听；检查自动停止。

**Architecture:** 录音保存与分析完成使用不同事件。分析和默写先预约同一轮编号（共享 Promise，处理评分未保存的边界），避免并发各建一轮。后台状态在默写页显示，完成只更新就绪提示；草稿保留音频供失败重试。

- [x] 增加服务端轮次预约与并发客户端共享编号测试。
- [x] 录音保存后进入默写；分析结束不停止播放、不滚动、不切页。
- [x] 后台分析时保留默写 Tab、空格、回车和底栏；错误提示可返回跟读重试。
- [x] 检查自动停设置、响度检测和最低发声时长，复现后修复。
- [x] 全部测试、浏览器延迟分析回归、最终审查、提交推送。

自动停止复现：声学最低时长永远不足、低声未被识别。改为提示音之前校准环境底噪，正常静音2.2秒，短尝试更长静音4.4秒兜底，仍受原句最短总时长限制。人工关闭自动停止时保持关闭。
浏览器用隔离数据、模拟麦克风和延迟的分析响应验证手机/桌面两种完成顺序；服务器真实默写接口与轮次预约经过测试。
