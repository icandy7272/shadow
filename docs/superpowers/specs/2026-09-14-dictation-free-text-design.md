# 默写改成一整行自由输入，按对齐判分

## 要解决的问题

现在默写是每个词一个框，判分也按框的位置一一对应：

- 写到后面发现中间漏了一个词，要把后面每个框里的词都往后挪一格，只能删了重写。
- 不挪的话，漏词之后的每个词都会被判错。一个词的疏忽，变成后面一整串错误。

## 做什么

### 输入

- 一整句写在一个输入框里，像平时打字一样，漏了词就把光标挪过去补上。
- 框下面显示「已写 N / M 个词」，M 是这句要写的词数（纯标点不算）。写多了数字变红。
- 不会的词打一个 `?`（半角、全角都行）。点「不会 ?」按钮，会在光标处插入一个 `?`。
- 回车就是对答案（输入法选词时的回车不算）。
- 输入框关掉自动大写、自动更正和拼写检查。手机上字号不小于 16px，免得 iPhone 点进去页面被放大。

### 判分

把写的词和原文的词按顺序对齐（最少改动的对齐方式），再逐词判：

| 结果 | 含义 |
|---|---|
| 写对 | 对上了，忽略大小写、标点、撇号（im 算 I'm 对） |
| 写错 | 这个位置写了词，但不是原文那个 |
| 漏写 | 原文有这个词，没写 |
| 不会 | 这个位置写的是 `?` |
| 多写 | 写了、但对不上原文任何一个词，单独列出来 |

- 漏一个词只算这一个漏写，后面照样对得上。
- 写错优先于「漏写 + 多写」：`i` 对 `I've` 算写错一个。
- 几种对齐一样好时，靠前的词先对上、缺的算在后面。比如只写到一半，缺的是后半句。

### 结果展示

- 统计行：写对 · 写错 · 漏写 · 不会，有多写时加一项多写。
- 整句逐词着色：标点照原文放。写错有波浪线；漏写有点状下划线，悬停提示「没写」；不会有虚线。
- 有多写时，单列一行「多写了：…」。
- 写错、漏写、不会的词逐个给释义。不会的自动进生词本，写错和漏写的有「加入生词本」按钮。

## 接口

`POST /api/dictation`：

```json
{"segment": 1, "unit": 6, "text": "and this is the closest i ever gotten to a ? graduation", "replays": 2}
```

返回（在原来基础上）：

- `missing`：漏写几个。
- `extras`：多写的词。
- `items[].status` 多一种 `missing`。
- `line`：整句每个词的 `lead`、`core`、`trail`、`status`（纯标点为 null），给前端着色用。

页面上默写这一步不再渲染原文的词和标点，前端着色全靠 `line`，对答案之前页面里没有原文。

数据库不变：`gapfill_correct` 记写对的数，`gapfill_total` 记要写的词数，`gapfill_unknown` 记不会的数。

## 代码

- `drill/dictation.py`：
  - 删掉 `Answer`。
  - `grade(words, text) -> Graded(marks, extras)`，用动态规划做词级对齐。
  - `tally(marks) -> (写对, 写错, 不会, 漏写)`。
  - 新增状态 `MISSING`。
- `web/app.py`：
  - 接口改为收 `text`，`text` 必须是字符串，最多 2000 字。
  - 返回 `line`、`missing`、`extras`。
  - 练习页上下文把 `tokens` 换成 `word_total`。
- `templates/practice.html`：第二步换成输入框、计数、「不会 ?」按钮、对答案。
- `static/app.js`：
  - 计数。
  - 回车对答案。
  - 在光标处插入 `?`。
  - 按 `line` 着色，列出多写。
  - 释义卡片认 `missing`。
- `static/app.css`：删掉逐词框的样式，加输入框和新状态的样式。

- `tests/test_dictation.py`：

  - `?` 和 `？` 都算不会。
  - 听错算写错，不拆成漏写加多写。
  - 多写单列，不挤乱后面的词。
  - 标点写不写都不影响。
  - 什么都没写就全算漏写。
  - 统计四类各几个。
- `tests/test_web_dictation.py`：
  - 练习页只有一个输入框和词数，默写这一步里没有原文。
  - 接口的统计、`items`、`line`、`extras`、写入数据库、不会进生词本。
  - 漏写一个词只算一个。
  - 释义只给没写对的词。
  - 格式不对返回 400。
