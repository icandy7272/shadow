# 跟读录音：说完了自己停

## 要解决的问题

每录一遍都得点一次「说完了」。戴着耳机、眼睛不在屏幕上时尤其别扭：说完还要找按钮，
那几秒的摸索会被录进去，也打断了「听完就说」的节奏。

## 做什么

录音时盯着麦克风的实时响度：**先出声、后安静一段**，就当这一遍说完了，自动收，接着走下一遍。
手动那条路原样留着——「说完了」随时能提前收，「这遍重来」照旧作废重录。

### 判据

三条同时成立才收：**连着静够久** + **真出声够多** + **录够久**。

| 参数 | 值 | 为什么 |
|---|---|---|
| `CALIBRATE_MS` | 300 ms | 开录后先量本底 |
| 本底取法 | 这 300 毫秒里的**最小**值 | 取最大值的话，嘀声一落就开口的人量到的是自己的嗓门，门限被顶得比说话还高，整遍都算静音——说到一半就收了。最小值即使在说话中间也仍接近底噪 |
| `FLOOR_CAP` | 0.01 | 本底再封一道顶 |
| 门限 | `max(本底 × 3, 峰值 × 0.07, 0.005)` | 峰值那一项要紧：嗓门轻的人整条曲线都低，只按绝对值卡，说着说着就被当成不说了。峰值自身按 0.995/拍 衰减，免得一声咳嗽把门限顶住整遍 |
| `SPEECH_MS` | 200 ms | 累计出声这么久才算开了口。没开过口就不猜，一直等人点 |
| `HUSH_MS` | 2200 ms | 连着静这么久才算说完。头几遍还没把句子顺下来时，句中犹豫能有两秒 |
| 最少出声 | 原声**真出声**时长 × 0.5 | 比的是词时长之和，不是整段时长——按整段算的话，跟得比原声快的人永远够不着，只能自己点 |
| 最短总时长 | 原声整段时长 × 1.3 | 头几遍说半句、卡两秒、再接上是常事。光看「静了多久」分不出犹豫和说完，就在这个点之前一律不收 |

代价是每遍末尾多出两秒多的静音。宁可多录两秒，也不能把人截断——截断了这一遍就废了，
还得重录。静音不影响分析：节奏和音高都从 ASR 认出的词算起，两端的静音本来就在测量之外。

### 关不掉就只能忍着，所以给了开关

跟读那一行加了「说完自动停」的勾选，默认开着，关掉就是从前那样一直等人点。
选择存在本机，下次进来还是这个选择。判据再怎么调也会有判错的时候，
那时候要的是一个开关，不是每遍都被截一次。

### 读不到响度就退回手动

分析用的 `AudioContext` 在 `getUserMedia` 之后单独开一个：iPhone 上先开上下文、后拿麦克风，
分析器常年读到 0。开不起来（点击的额度已经用掉了）就借放音那个；
浏览器没有 `getFloatTimeDomainData`（老 Safari）就整个放弃自动停。
这几条路上都只是回到「等人点说完了」，不拦着人练；状态栏的提示也跟着换。

## 代码

- `static/app.js`：
  - `createSpeaker()` 把 `ctx` 暴露出来当备用上下文。
  - `listenTo(stream, spare)`：接一个 `AnalyserNode`，返回读当前 RMS 的 `level()` 和 `close()`。
  - `recordOne(stream, ear, minSpoken)`：多一个 50 ms 的监视器，判据如上；`finish()` 里清掉。
  - 录完走 `wrapUp()`：原来那条路只停了轨道，没关上下文——一次点「开始」漏一个，
    几轮之后浏览器就不再给新的了。现在多开一个分析用的，更不能漏。
- `templates/practice.html`：`#practice` 上加 `data-seconds`、`data-spoken`，
  跟读那一行加「说完自动停」的勾选，提示语改成「说完停一下就自动收」。
- `web/app.py`：练习页的上下文多一个 `spoken`——原声里真出声的时长（词时长之和）。

## 测试

浏览器里的录音流程本来就没有自动化测试（没有 JS 测试环境），这次也只补得了模板那一头：

- `tests/test_web.py`：练习页带上原声时长和真出声时长，「说完了」那颗按钮还在。

判据本身是拿合成的响度曲线跑过的（正常、嘀声一落就开口、嗓门轻、句中停 1.2/1.5/2.5 秒、
头几遍说半句卡两秒再接上、跟得比原声快、长句、中途咳嗽、说一半就放弃），
每一档都在人真正说完之后 2.1–2.7 秒才收，没有一档提前截断；「说一半就放弃」不自动收，
留给人自己点。这段脚本没进仓库——没有 JS 测试环境，进来也没人跑。
