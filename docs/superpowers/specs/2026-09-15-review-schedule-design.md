# 复习排期：到期日、急迫程度、每天封顶

## 要解决的问题

「该复习」原来的规则是：昨天练过 **或** 还有问题没解决 **或** 盲听自评 ≤2。三条都是「当下的状态」，
没有时间轴，于是：

- 3 天前、7 天前练的句子，只要当时表现还行，就再也不会回来——而那正是最该复习的时间点。
- 有问题的句子永远留在筛选里，没有毕业机制，慢慢堆成一堆老大难。
- 列表按原文顺序排，点进「该复习」还是从头往下做：最早练的被复习得最多，而它们恰恰最熟；
  越靠后的越轮不到；时间被旧句子吃光，新句子进不来。

人手上的应对是「每天从头再读一遍练过的全部」，队列越长越读不完，最后天天在原地读前几句。

## 做什么

### 每句一个到期日

练习记录从头走一遍，算出这句现在在间隔阶梯的第几级：

| 这一轮的结果 | 判据 | 级别 |
|---|---|---|
| 往后推 | 盲听自评 ≥4，并且没有还挂着的问题 | 往后走一级 |
| 原地不动 | 自评 3 分，或者这轮没打分 | 不变 |
| 打回 | 自评 ≤2，或者上次的问题还挂着 | 回到第 0 级 |

阶梯是 `1 → 3 → 7 → 14 → 30` 天，从 -1（没练过）起步，所以第一次练完落在 1 天——
和日课里「先复习昨天练的」对得上。到期日 = 最后一次练的日子 + 这一级的天数。

「还挂着的问题」是累计的，不是这一轮的：只做了盲听、没录音的轮次，上一次没解决的问题不会因此就算解决。

到期日不存库，每次都从记录算。评分规则以后再改，老记录跟着重算，不会留下一批按旧规矩排的队。

### 「该复习」变成一条排好序的队列

- 选中：`到期日 <= 今天`。今天才练的到期日在明天以后，自然排除。
- 排序：老问题没解决 → 盲听没听懂 → 单纯到期；同一档里逾期越久越靠前。
- 封顶：一天最多 `DAILY_REVIEW = 8` 句，多出来的顺延，首页写明还压着几句。
  今天已经复习掉的句子（练过不止一轮、最后一轮在今天）占掉名额——否则练一句、
  后面又补上来一句，上限形同虚设。

列表上的「下一句」跟着同一个顺序走，不再按原文顺序。刚练完的那句已经不到期、掉出队列了，
「下一句」就从队头接着走——最急的那句。

## 代码

- `src/shadow/plan.py`：`INTERVALS`、`DAILY_REVIEW`、`GOOD_RATING`；
  `result_of`、`next_level`、`due_day`、`is_due`、`urgency`。`needs_review` 去掉。
- `src/shadow/filters.py`：
  - `State` 加 `due`。
  - `Selection(order, deferred, resorted)`：一个筛选选中哪几句、按什么先后走。
  - `select(name, states, today, *, usable)`：整条列表一起算，「该复习」在这里排序和封顶。
  - `after`/`before`/`remaining` 改成走 `Selection`，`after(..., wrap=False)` 给不带筛选的翻页用。
- `src/shadow/web/app.py`：`_practice_states` 顺带算级别和到期日；首页给每行带上 `review_rank`；
  `_place` 两个分支都用 `Selection`。
- `templates/index.html`：行上多一个 `data-review-rank`；卡片在名额用完时说「今天的复习做完了」。
- `static/app.js`：点「该复习」时按名次重排表格，别的筛选回到原文顺序。
- `templates/plan.html`：新增「复习怎么排队」；「还缺的两样」少了一样。

## 测试

- `tests/test_plan.py`：三种结果的判据；阶梯一级一级往上、到顶不再推、打回第 0 级；
  第一次练完是明天；到期的判断；急迫程度的先后。
- `tests/test_filters.py`：别的筛选保持原文顺序；练不了的句子不占名额；
  最急的排最前；封顶和顺延；今天复习掉的占名额、今天第一次练的不占；
  队列按急迫程度走「下一句」。
- `tests/test_web_plan.py`：练对一次就往后推一级（昨天练的今天不再来）；
  最急的那句排第一，练习页的「下一句」跟着走。
- `tests/test_web_queue.py`：「早就练好了」现在要练对五次才够——练一次就再也不回来，正是这次要修的。
