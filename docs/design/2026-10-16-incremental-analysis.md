# 加录增量分析

旧实现把数据库已有音频与新音频合并后重新运行完整分析，所以第 4 遍会触发原声及之前三遍再次转写和韵律分析。录音不重复入库，但耗时重复。

现在每次成功分析会在数据目录的 analysis-cache 下原子写入 JSON。原声保留韵律、校正时间戳和不可靠词索引；每遍保留转写、对齐、diff、节奏、音高及建议。缓存键包含音频内容、路径、原声文本／时间戳、模型及分析相关源文件内容，避免不同句子或规则变化混用结果。只解码允许的数据类型，不使用 pickle。

加录复用已有单遍结果，只对新增录音运行耗时分析，然后重新计算全轮汇总；遍数、顺序、中位数和代表遍与完整重算一致。进度总数只包含实际未缓存任务。提交重试和服务重启也可复用。缺失、损坏或失效的缓存补算；写入缓存失败不丢弃成功分析结果。

上线前没有完整缓存的旧录音首次仍需补算。缓存是派生数据，不替代原始录音或练习记录。无用户练习数据进入 Git。

验证覆盖三遍后新增第四、第五遍；重复提交不重复转写；重新打开缓存后复用；修改音频只重算受影响项；原声文本变化失效；缓存损坏与不可写回退；增量与全量汇总相同。
