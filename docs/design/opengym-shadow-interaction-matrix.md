# openGym × Shadow：手机 App 交互清单与讨论表

核验日期：2026-10-14。openGym 源码：e348fc17c42c7e9a211c5972e573ad3698190ee2；Shadow：e3a6ae6。本文件是讨论清单，不是实施批准，也不修改正式界面。

核验方式：完整读取 openGym frontend 页面、通用组件、浮层、会话状态与样式；实际演示核验首页、Resume、训练页、组次菜单、努力程度评分、完成勾与休息栏、提前结束确认、保存后完成摘要。其他条件页面为源码核验，不声称已在实体手机逐项操作。按交互类型去重，同类型在不同页面出现不重复列成独立组件；页面特有的行为另列。

复用分类：
- 直接：外观、布局、动作与状态规则可沿用，接到 Shadow 数据。
- 适配：保留交互结构，但替换健身语义，并实现所需的数据/会话能力。
- 可选：控件形态可复用，但对应功能尚不是 Shadow 的已确认需求。

“原生手机 App”目标：同一导航层级、可预测返回、固定拇指操作区、真实 sheet 手势与键盘适配、稳定完成反馈、返回恢复位置、安装后独立窗口。不能仅依靠圆角、配色和底栏判断已达标。

## 原生 App 讨论基准

1. 页面只承担一层任务，第二层优先详情sheet或独立详情页。
2. 统一底栏、标题栏、菜单、sheet、按钮和完成状态；不混杂桌面popover、原生alert和另一套自绘确认。
3. 键盘弹出后动作仍在可见区；面板关闭后不跳页；返回先退浮层，再退页面。
4. 点击整行/日期/指标有明确结果；状态可继续、可回看、可恢复，不只是静态装饰。
5. 保存成功才完成；录完、上传、分析、失败、完成分别展示。
6. 当前默认三遍后仍可第4、第5遍追加同一轮；不增加“加练前后对比”的新分支。
7. 触摸手势提供按钮替代；不能拦截系统边缘返回、图表选段或正常文本编辑。
8. 如做会话最小化，须先提供可靠草稿和录音生命周期，而非仅换路由。
9. 允许放大，补齐对话框语义/焦点管理。openGym原组件的这些细节不必盲目复制。
