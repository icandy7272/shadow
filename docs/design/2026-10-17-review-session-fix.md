# 跨天复习恢复修复

## 根因

手机 App 化的 b1f07d8 增加 IndexedDB 会话恢复。会话按句子地址与复习筛选保存，没有区分跨天的新一轮和同日继续；已完成并停在 record 的旧快照也会恢复。这是新增恢复功能的边界遗漏。

## 规则

已成功分析、没有待提交录音且最后保存日期早于设备今天时，加载为新练习，从盲听开始。当天结果查看、未完成草稿、含待提交录音的会话照常恢复。保留旧 storageRevision 进行后续并发检查，不直接删除练习记录或音频。完成会话不再推荐为继续入口。

原有“多次默写全对后自动跳过默写”规则保留：先完成本次盲听评分后才适用，不能让页面初次进入就跳过盲听。

## 验证

覆盖昨天已完成复习、新轮安全保存、同日结果恢复、跨天待提交 Blob、跨天未完成文字草稿以及既有并发保存与恢复测试。没有读取或删除用户浏览器实际练习数据，因此只能确认代码中这一缺陷，不能排除用户设备上另有未完成草稿。

## 后续复现与补充修复

仅按 updatedAt 判断跨天不充分：查看昨天结果后，自动保存可能把 updatedAt 改成今天，导致旧结果继续恢复。实际服务记录中该句 last_day 为 2026-10-16、due 为 2026-10-17，因此今天选中它符合队列，错误在于把新复习解释成旧结果查看。

今日、日课、练习入口及复习下一句增加一次性的 start=1 意图。会话标准地址仍不变；参数消费后立即从地址移除，保证刷新不反复重置。只有已完成且没有待提交音频的结果会开始新轮，保留存储版本进行并发安全写入；新一轮的盲听状态先持久化，刷新不会回到旧分析。未完成草稿及待提交录音仍恢复。

隔离浏览器复现了“刚自动保存、计时1500分钟、第三步已完成”的旧状态；明确开始后盲听、计时归零、旧结果不展示，刷新保持盲听。没有更改用户历史记录与音频。
